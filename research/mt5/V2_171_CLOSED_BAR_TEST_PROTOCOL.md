# AUREON FVG V2.171 Closed-Bar Diagnostic — MT5 Test Protocol

## Patch scope
- Control: original `FVG_Scalper_V2_17_FORWARD_VALIDATION.mq5`; preserve unchanged.
- Candidate: `research/mt5/FVG_Scalper_V2_171_ClosedBarDiagnostic.mq5`, generated by the patch script.
- Single strategy change: bullish and bearish rejection confirmation now uses the last closed candle's close (`r[1].close`) rather than the current forming candle and live Bid/Ask.
- Telemetry outputs are renamed to `FVG_V2_171_Diagnostic.csv` and `FVG_V2_171_Forward.csv` so candidate logs do not mix with V2.17.
- Re-entry, risk, reward/risk, filters, spread limits, and management remain otherwise unchanged for an isolated A/B comparison.

## Before testing
1. Copy the original V2.17 source into `C:\Users\User\Desktop\AUREON` (or a subfolder). The patch script searches this root and requires exactly one source file.
2. Run `apply_v2_171_closedbar_patch.ps1` from PowerShell. It creates a new candidate and a patch report; it will not overwrite the original or an existing candidate.
3. In MetaEditor, compile both control and candidate separately. Save the compiler logs. If either fails, stop and share the errors; do not run an uncompiled candidate.
4. Confirm the terminal account is PXBTTrading-1 DEMO. Keep live trading blocked.

## Controlled A/B test
- Same XAUUSD symbol, broker/server history, test dates, M1 entry timeframe, initial deposit, leverage, terminal build, inputs, and modelling mode.
- Run both with **Every tick based on real ticks**.
- Save each HTML report, Journal, test configuration, trade list, and source hash.
- Verify tester completion and modelling mode from the tester evidence. A large tick count alone does not prove the correct EA/test ran.
- Audit real-tick history coverage over the full date range; if data is missing or fallback occurs, mark the run **UNVERIFIED**.
- Compare trade count, net profit, gross profit/loss, profit factor, expected payoff, equity drawdown, average trade duration, spread/slippage and per-trade outcomes. Do not compare final balance alone.
- Do not tune more parameters until this one-variable comparison is understood. Use a separate unseen period for confirmation.
